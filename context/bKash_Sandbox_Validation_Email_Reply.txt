PART 2: ERROR CODE IMPLEMENTATION VALIDATION
======================================================================

We have implemented error code mapping according to bKash's official error catalog (https://developer.bka.sh/docs/error-codes). 
For cancelled and failed callbacks, our backend does NOT call the Execute API. Instead, it immediately records the provider state and displays clear feedback to the customer.

Case#A (Duplicate Transaction)
• Scenario: Two transactions initiated within 5 minutes with the same amount. The second transaction triggers bKash error code 2029 ("Duplicate for all transactions"). Customer is shown a clear "Payment Failed" heading with the exact reason and a "Back to home" button.
• Invoice number: MN-20261013-0005-01
• Payment ID: TR00116Zr5hJZ1791890986014
• Time of Transaction: 05:30pm Oct 13 2026
• Screenshot: Attached in document (Page 5)

Case#B (Cancel Payment)
• Scenario: Customer clicks Close/Cancel on the bKash payment window. Browser is redirected to cancelledCallbackURL. Customer is shown "Payment Cancelled" with "Payment was cancelled." message and a "Back to home" button. Execute API was not called.
• Invoice number: MN-20261013-0003-01
• Payment ID: TR0011ur46kzL1791886294584
• Time of Transaction: 04:12pm Oct 13 2026
• Screenshot: Attached in document (Page 5)

Case#C (Wrong OTP Exceed)
• Scenario: Customer entered invalid OTP three times deliberately on the bKash payment window. bKash returned error and redirected to failureCallbackURL. Customer is shown "Payment Failed" message and a "Back to home" button. Execute API was not called.
• Invoice number: MN-20261013-0004-01
• Payment ID: TR0011RFrPPVu1791888643661
• Time of Transaction: 04:51pm Oct 13 2026
• Screenshot: Attached in document (Page 6)
